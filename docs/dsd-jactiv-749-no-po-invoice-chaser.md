## 1. Solution Overview

Queries Coupa for invoices (past 7 days, status `draft`/`new`), excludes credit notes and PO-linked invoices, and posts one Slack Block Kit alert to the AP SME when unmatched invoices exist. Silent exit on a clean day. Read-only — no Coupa writes.

| Project | Role | Entry point |
|---|---|---|
| `no-po-invoice-chaser-api` | Primary — sole project in solution | `Workflow.json` (schedule-triggered; no caller inputs) |

## 2. As-Built Architecture

```
Orchestrator trigger (Mon–Fri 10:00 Europe/Bucharest)
        │
        ▼
no-po-invoice-chaser-api  [Workflow.json]
        │
        └─ TryCatch_1
              │ try                                        catch
              ├─ Javascript_ComputeDateWindow          Javascript_LogError
              ├─ HTTP_Request_Coupa  →  Coupa           → run fails; no Slack
              ├─ Javascript_FilterAndCount
              ├─ If_1 (qualifyingCount > 0)
              │     Then: Javascript_ComposeSlackPayload
              │           HTTP_Request_Slack  →  Slack
              │           Javascript_ValidateSlack
              │     Else: no-op
              ├─ Javascript_LogResult
              └─ Response_1
```

**As-built deviation:** `TryCatch_1` wrapping `Sequence_1` was added by the builder; the SDD §4.5 reference omitted it, but SDD §4 error-boundary text required it. The delivered `code/no-po-invoice-chaser-749/no-po-invoice-chaser-api/Workflow.json` is authoritative.

Both external calls use `UiPath.Http` through Integration Service; no credentials are embedded in the workflow file.

## 4. Exception and Error Handling

| ID | Condition | Detected at | Retry | Outcome |
|---|---|---|---|---|
| S1 | Coupa API error / bad response | `HTTP_Request_Coupa` | None | Catch logs; run fails; no Slack |
| S2 | Slack `ok !== true` | `Javascript_ValidateSlack` throws | None | Catch logs; run fails |
| S3 | Network timeout | Any HTTP activity | None | Catch logs; run fails |
| S4 | Invalid / expired credential | `HTTP_Request_Coupa` or `HTTP_Request_Slack` | None | Catch logs; run fails |
| S5 | Unhandled exception | Any activity in `TryCatch_1` | None | `Javascript_LogError` logs `$error.title`; run fails |
| B1 | Credit note | `Javascript_FilterAndCount` — `invoice-type === 'Credit Note'` | N/A | Excluded; logged in `exclusionLog`; continues |
| B2 | Description-only PO | No line-level `po-number` / `order-header-num` | N/A | Counted as qualifying (BR-02) |
| B3 | Clean day | `If_1` — `qualifyingCount === 0` | N/A | No Slack; `slack_sent: false`; run successful |

## 5. Operations Runbook

**Trigger:** `jactiv_749_weekday_trigger` — Mon–Fri 10:00 `Europe/Bucharest`. No inputs.

**Manual run:** Orchestrator folder `no-po-invoice-chaser-749` → **Start Job** — no arguments.

**Expected runtime:** < 10 s. Up to 50 invoices per run (current `limit` cap).

**Normal log sequence:** `Workflow start` → `Compute date window` → `HTTP Request: Coupa` (200) → `Filter and count` → (if count > 0) `HTTP Request: Slack` → `Validate Slack response` → `Log result` (`qualifying_count=N`, `slack_sent=…`) → `Response` (`status: "Successful"`).
